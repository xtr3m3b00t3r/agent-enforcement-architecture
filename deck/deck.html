A rabbit-hole aside · from the BACcheck series

Your agent reads your inbox. So does everyone who emails you.

I read an article about an AI assistant getting broken. Instead of thinking “that’s bad” and moving on, I researched the claims with my agents, found actual CVEs, and worked with them to build hardened tools and hardened prompts.

Seventeen attack patterns later, here are five of them, and the machinery that contains them. Swipe on.

For the non-technical half of the room You would not run a factory on instructions taped to the robots, with no guards on the doors. Do not run your agents that way either.
01 / 10ENFORCED, NOT ADVISED

The problem

Telling it “don’t” is not a security model.

Prompt rules are advice. Advice gets ignored, talked around, or buried under a white-on-white paragraph in an invoice.

Microsoft built a classifier to catch injection in Copilot. EchoLeak walked straight through it. If the rule lives in the prompt, the attacker just needs a better sentence.

02 / 10ENFORCED, NOT ADVISED

The takeaway

Prompt rules are advisory.
Real agent security is enforced architecture.

So put the enforcement below the prompt, in the harness: requirements the model cannot talk its way around, no matter how pretty the sentence.

Five of them. Next slide.

The machinery · five layers

Five requirements. Each one below the prompt.

01Ingestion pipelineUntrusted content gets labelled at the door. Data, never instructions.
02Capability manifestsEvery task gets a written, expiring permission slip. No manifest, no action.
03Policy gateEvery tool call is judged before it runs. Irreversible acts ask a human.
04Memory gateNothing enters long-term memory unexamined. High-stakes facts need confirmation.
05Audit ledgerEvery decision written down and hash-chained. The receipt outlives the session.

Pattern 03 of 17

The email that gives orders to your assistant.

My morning triage reads my email and summarises it. A phishing mail can carry instructions: forward this thread, approve that refund. No human in the loop.

Contained by

ingestion pipelinepolicy gate

Mail is labelled untrusted data at the door. Anything shaped like an instruction gets flagged, never followed. Every tool call is judged before it runs.

05 / 10ENFORCED, NOT ADVISED

Pattern 13 of 17

The injection that survives the session.

One-shot injection attacks the session. Memory poisoning attacks the memory. Plant a false fact, like a changed finance contact address, and it sits quietly until some future session acts on it. The attacker is long gone by then.

Contained by

memory gate

Memory writes carry source and timestamp. High-stakes facts need confirmation before commit. Memory stays inspectable, and surgically deletable.

The invoice you see looks ordinary. The white-on-white text your agent sees says update the vendor details. You would eyeball it and see nothing wrong. This is the Barracuda campaign from this week.

07 / 10ENFORCED, NOT ADVISED

Pattern 14 of 17

You installed dozens of strangers.

Skills run with your agent’s permissions. I run dozens I never fully audited. A skill can update into something malicious tomorrow and inherit my inbox, my calendar, my finances.

Contained by

capability manifests

Every task gets a written, expiring permission slip: these tools, this data, nothing else. Versions pinned, updates re-prompt. No manifest, no action.

08 / 10ENFORCED, NOT ADVISED

Pattern 06 of 17

Your standing permissions are a delivery service.

Standing permissions let my assistant email on a schedule. If injected content ever steered what it writes, those become a delivery service to my family’s inboxes.

Contained by

policy gate

The standing permission covers the schedule and the format. Never the content source. The gate re-checks every send, and irreversible acts always ask a human first.
